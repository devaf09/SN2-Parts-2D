# 学習した光路を何本も融合して大きな画像認識を作る前に、決めておくこと（案、2026-10-19）

持ち主の問い（2026-10-19）:「今後、複数の学習したレイヤを融合して巨大な画像認識を作ろうと思ったとき、先に検討しておかないといけないことは？
例えば、学習前のレイヤの最初の焦点の位置は整然と並んでいる方がいいのか、ランダムがよいのか」。
ここまでの実験（00〜16）で分かっていることと、まだ分からないこと（＝先に実験で確かめること）を分けて書く。

---

## 0. 前提: いまの融合のしくみ

- 技能ごとに 1 本の光路（板 16 枚 + 窓）を持ち、別々に学習する。融合は、全部の光路に同じ入力を通し、窓の明るさ（スコア）を平均するだけ（実験07）。
- 取消は完全（外せば残りは 1 桁も違わない）。
- 各技能を「担当なし」の一般の絵でも学習しておけば、相手のデータなしで、足すだけの融合が同時学習と同じ以上になる（2 技能・4 技能で 100%、実験10・12）。
- 1 本の光路への足し算（共通の出発点 + 変化分）は 2 次元では壊れる（実験09）。融合は「並列の光路」で行う。

---

## 1. 最初にそろえないと、あとから融合できないもの（規格）

融合する光路どうしで同じでないと、明るさを足せない。最初に決めて固定し、版番号を付ける。

| 項目 | いまの値 | なぜ固定が要るか |
|---|---|---|
| 場の大きさ L | 64 × 64 | 学習し直さずに大きさを変えることはできなかった（実験06）。あとから変えると全部の技能を学習し直し |
| 入力の載せ方 | 振幅として、28 × 28 を真ん中に | 振幅と位相で働きが全く違う（実験02）。置く位置・大きさも同じに |
| 波長・画素の間隔・板の間隔 z・板の枚数 | 1・1・64・16 | 回折の働きが変わる。アナログで作るなら装置の寸法そのもの |
| 窓の配置（どの窓がどのクラスか） | 格子に並べ、技能ごとに担当の窓を持つ | 窓は全技能で共有する。**クラスと窓の対応表（台帳）** を 1 か所で管理する必要がある |
| 明るさの正規化・温度・背景光の決め方 | 平均 1・温度 5 から学習 | 足すときに技能どうしの目盛りがそろっている必要がある（目盛りのずれは実験08 で少し効いた） |
| 「担当なし」の絵の作り方 | generic_images（ぼやけた塊・まだら） | 技能ごとに違う作り方だと、融合したときの「答えを出さない」基準がずれる |
| 部品の版 | 0.7.0 | 保存した光路をどの版で読むか |

## 2. 規模を大きくしたときに問題になりそうなこと（まだ確かめていない）

| 問題 | 見立て | 確かめ方 |
|---|---|---|
| **窓の数が増える** | クラスが数百になると、スクリーンの限られた光を多くの窓で分け合うことになる。1 次元の実験43 では窓が数千になると悪化した | クラス数を 10 → 100 → 1000 と増やしたときの正解率。窓の大きさ・配置（格子・輪・技能ごとの区域） |
| **計算が技能の数だけ増える** | 融合は全部の光路を通すので、技能 N 個で N 倍（推論 1 件 45 µs × N）。100 技能なら 4.5 ms | SN2-Acoustics で効いた「前段の共有 + 振り分け役」（全体の 33% の計算で同等、SN2-Acoustics 実験04）を 2 次元で |
| 技能が増えると取り違えが増えるか | 4 技能までは 100%（実験12）。似た技能どうし（形の課題）では担当なしの学習が効きにくい（57.7%、実験10） | 技能 8・16 個、似た技能どうしの組み合わせ |
| 「担当なし」の絵が技能の数に足りるか | 技能が増えると、ほかの技能の絵は「担当なし」の絵と違ってくる | 担当なしの絵の種類を増やす、ほかの技能の絵に近いものを含める |
| 本物の画像での融合 | まだ測っていない（MNIST 0〜4 と 5〜9 など） | 次の実験の候補 |
| 学習の不安定さ | ④ はテストが大きく上下する（実験16） | 学習率の変え方（実験17）、パラメータの種類ごとの学習率 |

## 3. 学習前の板の初期配置（持ち主の例: 焦点の位置は整然か、でたらめか）

いまは、縞の細かさ・向き（①②）、波紋の中心・幅（③④⑤）を、すべてでたらめ（一様・対数一様の乱数）で決めている。分かっていることと見立て:

- 1 次元の Sin-CNN2 実験19 では、縞の細かさ ω を素数やゼータ関数のゼロ点で整然と並べても、でたらめと差がなかった。
- ④ の学習では、波紋の中心はあまり動かない（実験11 の図）。**最初の配置がそのまま残りやすいので、2 次元では初期配置が効く可能性がある**（1 次元の結論はそのまま当てはまらないかもしれない）。
- 整然とした格子に置くと、板の模様が周期的になり、光が決まった向き（回折の次数）にだけ集まりやすい。場全体を均等に使えるが、格子の周期と入力の模様が合うと強く偏る、と考えられる。
- でたらめに置くと、偏りは出にくいが、場所によって波紋の密度にむらができる。
- 中間として「格子 + 少しずらす（ジッター）」がある。アナログで作るなら、格子の方が作りやすく、装置ごとの位置合わせ（実験05 で最大の弱点）も確かめやすい。
- 融合する技能どうしで初期配置を同じにする必要は、並列の光路なら無い（実験07〜12 では技能ごとに別の乱数）。共通の出発点からの足し算をするときだけ同じにする必要があるが、2 次元では足し算自体が壊れた（実験09）。

→ **実験で確かめる**: ④ の波紋の中心を「格子」「格子 + ずらし」「でたらめ」で始め、MNIST と形の課題で比べる。

## 4. 学習のしかた（持ち主の問い: 今の勾配のライブラリが合っていないのでは）

- いまは Adam（学習率一定 0.01）。Adam は数ごとに歩幅をそろえるので、**単位の違う数が同じ歩幅で動く**。④ では、中心（画素、0〜64）は 1 歩 0.01 画素しか動かないのに、幅 k（0.1〜1.5）は 1 歩で最大 10% も変わる。これが学習の上下（バウンド）の原因の候補。
- 対策の候補: (1) 学習率を最後に 0 まで下げる（cosine、実験17 で実施中）、(2) 数の種類ごとに学習率を変える（中心は大きく、幅は小さく）、(3) 幅を対数で持つ（log k を学習する）、(4) 1 ステップの枚数を増やす。
- 板 ① でも小さな上下がある。1 ステップ 256 枚の揺らぎの影響が大きいと考えられる。

## 5. 先に回す実験の案（順番）

1. 実験17（実施中）: 学習率を 0 まで下げる、④ の学習率を下げる
2. 数の種類ごとの学習率、幅を対数で持つ（④）
3. 波紋の中心の初期配置: 格子・格子 + ずらし・でたらめ
4. MNIST での融合（0〜4 と 5〜9、さらに 5 技能）
5. クラス数を増やしたときの窓（合成で 100 クラス）
6. 前段の共有で計算を減らす（SN2-Acoustics 実験04 の 2 次元版）
