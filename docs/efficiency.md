# 効率の一覧 — 光の部分とデジタルの部分を分けて（2026-10-21）

持ち主の依頼（2026-10-21）: 計算量の問題を効率の一覧にまとめる。
Sin-CNN（03_Opticlm）の自己批判「重さの 98% はデジタルの部分」にならい、学習する数を**光の部分**（板の模様、位置ごとの明るさ、倍率）と
**デジタルの部分**（符号読みの符号、窓ごとの背景光、温度）に分けて書く。時間は RTX 3060 での学習の時間（1 本、seed 0 か 3 seed の平均）。
数字の正本は NOTES.md。

## 読み方

1. **今の計算機では、光の模擬はどれも普通のネット・n-gram より 20〜200 倍遅い。** 正解率で並べても、時間では勝てない。
2. **言語の光路は、学習する数の大半がデジタルの符号**（単語で 98%、文字で 80%）。答えの種類が多いほど、デジタルの部分が重くなる。
   「光で計算する」部分は板の数万個だけで、ハードで速くなるのもこの部分だけ。
3. **分担の 2DTG は、光の数・デジタルの数をそろえても 1 本より良い**（文字 51.3 → 54.0、単語 33.3 → 36.0）。ただし 2DTG ごとに自分の符号を学ぶことが条件（実験64）。
4. ハードで速くするなら、デジタルの符号（窓の明るさ × 符号の掛け算、窓 K × 答え C 回）を減らす工夫が要る。
   たとえば、1 クラス 1 窓（符号なし、デジタルは背景光だけ）で読める形にする、符号の掛け算も 2 枚目の光路（4f 系）で行う、など。
5. ハードの速さの見積もりには、空間光変調器の書き換え（kHz 程度）・カメラの読み出し・ADC を含めていない（Sin-CNN の REVIEW と同じ弱点）。
