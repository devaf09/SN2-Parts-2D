# 会話プロジェクトの企画（SN2-Parts-2D からの引き継ぎ、2026-10-23）

持ち主の依頼（2026-10-23）: SN2-Parts-2D の言語の実験のうち、会話の部分の企画をまとめる。新しいプロジェクトを作るセッションがこれを読み、
新しいプロジェクトのプロンプトと使う材料にして、会話の研究を続ける（並行するプロジェクトが多いので、進みはゆっくりでよい）。

この文書だけで始められるように書いた。数字の正本は SN2-Parts-2D の NOTES.md（実験31〜72）。

---

## 1. 目的と持ち主の方針

- **目的**: SinWave（正弦の干渉と回折だけで学ぶ光の学習器）の部品で、日本語の**会話（チャット）**ができる仕組みを作る。
  文書の続きを当てるより、会話の方が持ち主の個人的な目的に合う（2026-10-22）。最終的に LLM を目指すわけではない。
- **持ち主の考え方**（会話の中で出たもの）
  - 小さな学習器を並べて融合する。1 つの大きな学習器にはしない（「2DT グレイン（2DTG）」= 2D のトークンから確率を出す小さな学習器）。
  - 日本語の敬語・一人称・語尾の多さを「逆手に取る」。話者を見分ける学習器（2DWIG = 2D Who am I Grain）を先に作り、
    次の語を当てる学習器に「隠し味」として混ぜる。二人称は 2DWYG（Who are You）、三人称は 2DWTG（Who are They）。
  - 完全より完成を目指す。
  - 会話のパターンが大量に要る。データを増やす・水増しする。GPU サーバーが要るかもしれない。
- **作業の約束ごと**（SN2-Parts-2D と同じ）
  - 報告は日本語。結果には比較の表と図を多めに入れる（図は docs/images/ に保存）。
  - データのダウンロードは、取得元・大きさ・ライセンスを示して許可を得てから。データ（data/）はリポジトリに入れない。
  - GPU は同時に 1 つの実験だけ。長い実験は待ち行列で切れ目なく回す（下の 6 節）。
  - 光の部分とデジタルの部分（符号読みの符号など）の重さを分けて数える（実験64・66 の教訓。Sin-CNN の自己批判と同じ）。
  - 有望な案・効かなかった案は記録に残す（同じ道を避ける）。

## 2. ここまでに分かったこと（言語、SN2-Parts-2D 実験31〜72）

### 2.1 光の学習器の性質
| 分かったこと | 数字 | 実験 |
|---|---|---|
| 光路 1 本は、全部の語が同じ板を共有するので、覚えられる対応表が小さい | 「1 語 → 次の語」でも 29.6%（表なら 33.6%）。板を倍にして +1 点 | 55・56 |
| データが少ないときは光が強い（覚えすぎにくい）。多いと伸び悩む | 2 万件で光 27.3% > GRU 25.7%。33 万件で光 32.7%、GRU 36.9% | 57 |
| 照明・参照波・光の記憶・鏡の往復・短冊・入れ方・板の間隔・語の並べ方は効かない | 差は ±1 点以内 | 34〜60 |
| 振幅 + 位相の板は、位相だけより良い | +2.2 点 | 63 |
| 光路は逆向きに通せる。答えを位相まで持たせれば（参照光と干渉させて読む）、出口から答えを入れて「前に来やすい語」を連想できる | 穴埋め 21.3 → 33.8% | 65・67 |

### 2.2 一番良い形: 分担の 2DTG（小さな光路に表を分けて受け持たせ、足すだけで融合）
| 課題 | 正解率 | 比べる |
|---|---|---|
| 文字（直前 4 文字 → 次の文字、64 クラス） | 54.0%（窓 256）/ **53.3%（窓 32・担当の決め打ち、学習する数 9.9 万）** | GRU 53.3〜54.1%（17 万）、3-gram 53.7% |
| 単語（MeCab、直前 2 語 → 1024 クラス） | 36.0% / **35.7%（窓 32・決め打ち、59 万）** | GRU 36.9%（76 万）、3-gram 36.4% |
| サブワード（SentencePiece 語彙 2048、その他なし） | 22.9% | GRU 22.8%、3-gram 24.9% |

- しくみ: 直前の語の番号の余りで担当を 16 に分ける。各 2DTG（板 ① 8 枚 × 区画 16 + 窓の符号読み）は自分の担当だけを学ぶ。
  担当は直前の語で決め打ち（ハードでは照らす光路をスイッチで選ぶだけ）。2DTG ごとに自分の符号を学ぶことが条件（固定すると効かない、実験64）。
- 光路 1 本に同じ重さの符号を持たせても伸びない（実験66）ので、分担の効果は本物。
- プログラム: SN2-Parts-2D/experiments/text/exp58_split.py（`--task char|word|sp --G 16 --layers 8 --K 32 --reject 0`）。

### 2.3 天井（直前の数語だけを見る形の限界）
- 同じ文脈の後に違う答えが来る分は、どれだけ鍛えても当たらない（例:「お願い」の次は「し」46%、「いたし」22% …）。
- 分担の 2DTG は、今のデータ（33 万語）での天井（後退つき n-gram・GRU で 36〜37%、文字 54〜55%）のすぐ下まで来ている。
- **天井を上げるには、別の情報（長い文脈・話題・話者）を入れること、データを増やすことが要る。** → 会話プロジェクトの出発点。

### 2.4 「その他」（語彙の外）
- 単語で答えの 20%。光は自信がないと「その他」に逃げる（41% の場面で一番に出す）。除いて並べ直すと +4 点（実験68）。
- 「その他」の中身はまれな名詞 67%・動詞 19%・固有名詞 4.5%。助詞（が・と・な）は頻出語の側にある。
- 2 段目（その他の中を受け持つ 2DTG）で確信度は大きく良くなる（CE 4.52 → 3.70）。サブワード（SentencePiece）なら「その他」自体がなくなる（実験69）。

### 2.5 関連度・差分・掛け算（数えた表での見積もり）
- 関連度（話題の近さ）で内容語だけを並べ替えると、内容語の位置で +2〜11 点。全部の語に掛けると悪化（機能語を押しのける）。光の関連度グレイン（50 語の袋）は学べなかった（実験54）。
- 差分（男 → 女 = 父 → 母）は 33 万語でも少し成り立つ（1 位）。
- 2DTG の出力の掛け算（専門家の積）は足し算より良いが、弱めて掛ける必要がある。1 単位ずつ見る形の天井は 3-gram より下。

### 2.6 話者の学習器 2DWIG（実験71・72）
| データ | いつも一番多い類 | 光の 2DWIG | ロジスティック回帰 | 数えた表（語尾・言い回しの袋） |
|---|---|---|---|---|
| 青空文庫 150 作品（一人称つき会話 3 千件） | 34.2% | 32.7%（覚えすぎ、訓練 100%） | 42.0% | 51.9% |
| 青空文庫 1,000 作品（2.3 万件） | 38.6% | **43.1%**（訓練 55%） | 44.8% | **52.7%** |
| 同 + 話者を変えた水増し 4,024 件 | 38.6% | 43.1% | 44.8% | 51.4% |

- 12 類: 私・僕・俺・わし・あたし・あっし・わたくし・我々・武士（拙者・身共・それがし）・おいら・わらわ・わちき。少ない類はほとんど当たらない。
- 入力は「一人称を隠した会話文の末尾 12 文字を位置ごとに並べる」より、「語尾・言い回しの袋」の方が良い。
- 水増し（一人称と文末を置き換え、本物の会話文で不自然なものを捨てる）は効かなかった。文の途中の口調は元の話者のまま残るため。
  効かせるには、呼び方・敬語など文の途中も置き換える必要がある。
- 話者の情報を「隠し味」に混ぜた場合の効果の見積もり（数えた表、150 作品）: 会話文の次の文字 26.9 → 27.7%（データが少ない）。

## 3. 会話に要る機能の一覧（優先度つき）
SN2-Parts-2D/docs/conversation_features.md（14 機能、優先度・状況つき）。要約:
- **高**: 長期・中期の記憶、文章の中の関連性、話し手・相手のモデル（2DWIG/2DWYG/2DWTG）、どう言うか（2DTG + 隠し味）、文を作り続ける仕組み、分からないときの扱い（担当なしの学習・確信度）
- **中**: 意図の理解、会話の流れ、何を言うかを決める、知識（逆向きの連想）、自分らしさの一貫性
- **中〜低**: アイディア（発想。部品の組み合わせ・差分・逆向きの連想で離れた知識を結び付ける。2026-10-23 追加）
- **低**: 気持ち・場の空気、良い・悪いの判断
- 光の部品にすぐ結び付く: 分からないときの扱い、知識。光だけでは難しい: 何を言うかを決める、文を作り続ける仕組み（外側の指揮役が要る）。

## 5. 決まっていないこと
- データ: 青空文庫だけで続けるか、現代の会話（名大会話コーパスなど、登録・条件あり）を足すか。さらに増やすか（著作権切れの新字新仮名の小説は約 4,500 作品）。
- 単位: 文字・単語（MeCab）・サブワード（SentencePiece）のどれで会話を作るか。
- 話者の正解の付け方: 一人称が出ない会話文に、同じ場面の同じ話者を推定してラベルを広げるか。
- 水増し: 文の途中（呼び方・敬語）まで置き換えるか、生成器で作るか。
- 計算: 分担の 2DTG は 2DTG ごとに別々に学べるので、複数の GPU に分けると素直に速くなる。クラウドの GPU を借りるか。
- 「何を言うか」「文を作り続ける」外側の手順を、何で作るか（光の部品の外）。

## 6. 最初の一手の案
1. **2DWIG の入れ方を袋にする**: 「語尾・言い回し（文字の 2 つ組・語尾 1〜3 文字）の袋」を光に入れる形にする（数えた表で 52.7%、光の位置並べは 43.1%）。
2. **話者の隠し味を 2DTG に混ぜる**: 会話文の次の文字・語を、話者の類ごとの分担の 2DTG を 2DWIG の成分で混ぜて当てる。混ぜない場合と比べる（150 作品の見積もりでは +0.8 点、1,000 作品で測り直す）。
3. **2DWYG（二人称・呼び方）**: 君・お前・貴方・〜殿・親分 などから、相手との関係を当てる。2DWIG と同じ作り方。
4. **文を作り続ける最小の手順**: 2DTG で 1 単位ずつ選び、繰り返しを避け、「」で閉じる。「その他」を除いて並べ直す（実験68）。

## 7. GPU の待ち行列（SN2-Parts-2D で使っているもの）
- Windows のタスクスケジューラに「SN2-Parts-2D GPU queue」を登録済み（持ち主の許可、2026-10-22。30 分ごと、画面なし）。
  tools/queue_runner.sh が results/queue.txt の sweep を上から順に回し、results/queue_done.txt に記録する。実験の python が動いていれば待つ。
- Claude のアプリが自動更新・終了すると、アプリから起動した処理は止まる。待ち行列と、終わった条件を飛ばす再開（tools/run_missing.sh）で対処。
- 別のプロジェクト（Project_Metasequoia）にも待ち行列（Metasequoia-GPU-queue）があるので、GPU を同時に使わないよう注意。
- 新しいプロジェクトで同じ仕組みを使う場合は、別の名前で登録し直し、不要になった登録は消す（持ち主との約束）。
